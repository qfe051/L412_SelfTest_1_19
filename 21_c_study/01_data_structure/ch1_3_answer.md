## Q1. 자료구조란 무엇인가?

### 모범답안

자료구조는 데이터를 효율적으로 저장하고 처리하기 위한 조직 방식이다.
프로그램에서 자료구조가 중요한 이유는, 같은 문제라도 어떤 구조를 선택하느냐에 따라 검색, 삽입, 삭제 속도와 메모리 사용량이 크게 달라지기 때문이다.

### 핵심 해설

자료구조는 단순히 “데이터를 담는 통”이 아니다.
**어떤 연산을 빠르게 할지 결정하는 설계**에 가깝다.

### 실수 포인트

* “데이터를 저장하는 방식”까지만 말하고 끝내는 것
* 처리 효율, 성능 차이까지 연결하지 않는 것

### 실무 연결

버퍼, 테이블, 리스트, 큐를 어떤 구조로 잡느냐에 따라 코드 복잡도와 성능이 달라진다.

---

## Q2. 자료구조와 알고리즘의 차이

### 모범답안

자료구조는 데이터를 저장하고 조직하는 방식이고, 알고리즘은 그 데이터를 처리하는 절차와 방법이다.
예를 들어 배열은 자료구조이고, 정렬이나 탐색은 알고리즘이다.

### 핵심 해설

* 자료구조 = “무엇 위에 저장할 것인가”
* 알고리즘 = “그 위에서 어떻게 처리할 것인가”

### 실수 포인트

* 배열과 정렬을 둘 다 자료구조라고 말하는 것
* 탐색을 자료구조라고 말하는 것

### 실무 연결

같은 배열을 써도 선형탐색, 이진탐색, 정렬 방식에 따라 처리 효율이 달라진다.

---

## Q3. 좋은 자료구조를 고르는 기준

### 모범답안

자료구조 선택 시에는 검색 빈도, 삽입/삭제 빈도, 메모리 사용량, 구현 복잡도 등을 고려해야 한다.
즉, 어떤 연산을 자주 수행하는지에 따라 적절한 구조를 선택해야 한다.

### 핵심 해설

“무조건 좋은 자료구조”는 없다.
**사용 목적에 따라 유리한 구조가 달라진다.**

### 실수 포인트

* 속도만 말하고 메모리나 구현 난이도는 빼먹는 것
* “배열이 제일 좋다”처럼 단정하는 것

### 실무 연결

임베디드에서는 메모리 제한 때문에 단순한 배열 구조가 더 유리할 때도 많다.

---

## Q4. 논리적 구조 vs 물리적 구조

### 모범답안

논리적 구조는 데이터가 개념적으로 어떤 관계를 가지는지를 나타내고, 물리적 구조는 그것이 메모리에 실제로 어떻게 구현되는지를 나타낸다.
예를 들어 리스트는 논리적 구조이고, 배열 기반 리스트나 연결리스트는 물리적 구현 방식이다.

### 핵심 해설

같은 “리스트”라는 논리 구조도

* 배열로 구현할 수도 있고
* 연결리스트로 구현할 수도 있다.

### 실수 포인트

* 리스트 자체를 물리적 구조라고 착각하는 것

### 실무 연결

같은 기능 요구사항도 고정 배열로 구현할지, 동적 노드로 구현할지 선택해야 한다.

---

## Q5. 추상자료형(ADT)란?

### 모범답안

추상자료형은 데이터와 그 데이터에 대한 연산을 하나의 개념으로 정의한 것으로, 내부 구현 방식은 숨기고 사용자에게 필요한 기능만 제공하는 자료형이다.
예를 들어 리스트 ADT는 삽입, 삭제, 탐색 같은 연산을 정의하지만, 내부적으로 배열을 쓸지 연결리스트를 쓸지는 별개이다.

### 핵심 해설

ADT는 **“무엇을 할 수 있는가”** 를 정의하고,
구현은 **“어떻게 할 것인가”** 의 문제다.

### 실수 포인트

* ADT를 그냥 구조체라고만 이해하는 것

### 실무 연결

인터페이스는 같고 내부 구현만 바꾸는 방식은 실무에서도 자주 쓴다.

## Q6. 알고리즘의 조건 5가지

### 모범답안

알고리즘은 일반적으로 입력, 출력, 명확성, 유한성, 유효성을 가져야 한다.
즉, 필요한 입력을 받아 명확한 절차로 유한한 단계 안에 실행 가능해야 한다.

### 핵심 해설

알고리즘은 “언젠가 끝나는 명확한 절차”여야 한다.

### 실수 포인트

* 효율성까지 넣어서 5대 조건처럼 말하는 것
* 유한성과 유효성을 헷갈리는 것

### 실무 연결

무한루프나 모호한 조건 분기는 좋은 알고리즘이라고 보기 어렵다.

---

## Q7. 시간복잡도란?

### 모범답안

시간복잡도는 입력 크기 n이 증가할 때 알고리즘의 수행 시간이 어떻게 증가하는지를 나타내는 척도이다.
실제 초 단위 시간보다는 비교 횟수, 반복 횟수 같은 연산 수를 기준으로 분석한다.

### 핵심 해설

시간복잡도는 “지금 몇 초 걸렸는가”보다
**입력이 커질수록 얼마나 느려지는가** 를 보는 개념이다.

### 실수 포인트

* 시간복잡도를 실제 실행시간 그 자체라고 생각하는 것

### 실무 연결

PC에서 빠르게 보이던 코드도 데이터가 커지면 갑자기 병목이 될 수 있다.

---

## Q8. O(1), O(n), O(n²) 직관 설명

### 모범답안

* O(1)은 데이터 크기와 관계없이 연산량이 거의 일정한 경우이다.
* O(n)은 데이터 크기에 비례해서 연산량이 증가하는 경우이다.
* O(n²)은 데이터가 커질수록 연산량이 제곱으로 증가하는 경우이다.

### 핵심 해설

이건 공식보다 **증가 속도 감각**이 중요하다.

### 실수 포인트

* O(1)을 “1번만 실행”으로만 좁게 해석하는 것
* O(n²)을 그냥 “느리다” 수준으로만 이해하는 것

### 실무 연결

중첩 루프가 들어가면 O(n²) 가능성을 먼저 의심해야 한다.

---

## Q9. 배열 접근이 빠른 이유

### 모범답안

배열은 메모리에 연속적으로 저장되므로, 시작 주소와 인덱스를 이용해 원하는 원소의 주소를 바로 계산할 수 있다.
그래서 `arr[i]` 접근은 순차 탐색 없이 직접 접근 가능하여 빠르다.

### 핵심 해설

핵심은 **연속 메모리 + 주소 계산**이다.

### 실수 포인트

* “배열은 원래 빠르다” 수준으로만 답하는 것

### 실무 연결

`arr[i] == *(arr + i)` 감각이 중요하다.

---

## Q10. 포인터가 필요한 이유

### 모범답안

포인터는 메모리 주소를 다루기 위해 필요하며, C에서는 동적 메모리 사용, 연결구조 구현, 함수로 원본 데이터 전달, 구조체 수정 등에 필수적이다.
자료구조에서는 특히 노드 연결과 원본 상태 공유를 위해 포인터가 중요하다.

### 핵심 해설

자료구조에서 포인터는 거의 필수 도구다.

### 실수 포인트

* 포인터를 단순히 “주소 저장 변수”까지만 설명하고 끝내는 것

### 실무 연결

`ring_st *r`, `uint8_t *buffer`, `Node *next` 전부 같은 계열의 사고다.

---

## Q11. 정적 배열 vs 동적 메모리

### 모범답안

정적 배열은 크기가 컴파일 시점에 정해지고 연속된 메모리를 사용하며, 크기 변경이 어렵다.
동적 메모리는 실행 중 `malloc`으로 필요한 만큼 확보할 수 있어 유연하지만, 직접 `free`로 해제해야 한다.

### 핵심 해설

* 정적 배열 = 단순, 빠름, 크기 고정
* 동적 메모리 = 유연, 관리 필요

### 실수 포인트

* 정적 배열과 지역변수를 혼동하는 것
* 동적 메모리 해제를 빼먹는 것

### 실무 연결

연결리스트는 동적 메모리가 없으면 구현 자체가 어렵다.

---

## Q12. 왜 연결구조가 필요한가?

### 모범답안

배열은 인덱스 접근은 빠르지만, 중간 삽입/삭제 시 많은 데이터 이동이 필요하고 크기도 고정적이다.
반면 연결구조는 노드를 포인터로 연결하므로 크기를 유동적으로 늘릴 수 있고, 특정 위치의 삽입/삭제가 더 유리하다.

### 핵심 해설

배열이 다 해결해주는 게 아니다.
**유동성**과 **삽입/삭제 효율** 때문에 연결구조가 필요하다.

### 실수 포인트

* 연결리스트가 무조건 더 빠르다고 말하는 것

### 실무 연결

데이터 개수가 실행 중 변하는 경우 연결구조가 자연스럽다.

## Q13. 리스트란?

### 모범답안

리스트는 순서가 있는 데이터들의 모임이다.
스택과 큐는 리스트의 특수한 형태로, 리스트의 연산 위치를 제한한 구조라고 볼 수 있다.

### 핵심 해설

리스트는 가장 일반적인 선형 구조다.

### 실수 포인트

* 리스트를 배열과 같은 뜻으로만 보는 것

### 실무 연결

리스트는 논리 구조이고, 구현은 배열/연결리스트로 나뉜다.

---

## Q14. 순서리스트와 연결리스트의 차이

### 모범답안

순서리스트는 배열 기반이라 메모리가 연속적이고 인덱스 접근이 빠르지만, 중간 삽입/삭제 시 이동이 필요하다.
연결리스트는 노드를 포인터로 연결하므로 메모리가 비연속적일 수 있고, 인덱스 접근은 느리지만 삽입/삭제가 더 유리하다.

### 핵심 해설

비교 기준은 반드시

* 메모리 구조
* 접근 방식
* 삽입/삭제
  로 나눠야 한다.

### 실수 포인트

* 한쪽이 무조건 좋다고 결론 내리는 것

### 실무 연결

고정 버퍼는 순서리스트형, 동적 노드 구조는 연결리스트형으로 보면 된다.

---

## Q15. 공집합 리스트란?

### 모범답안

공집합 순서리스트는 `length == 0` 으로 표현하고, 공집합 연결리스트는 `head == NULL` 로 표현한다.

### 핵심 해설

둘 다 “비어 있음”이지만 내부 표현 방식이 다르다.

### 실수 포인트

* 둘 다 NULL이라고 말하는 것
* 둘 다 size 0이라고만 말하는 것

### 실무 연결

자료구조별 공집합 표현을 명확히 구분해야 초기화/예외처리가 깔끔해진다.

---

## Q16. 순서리스트의 내부 표현

### 모범답안

순서리스트는 보통 실제 데이터를 저장하는 배열과 현재 저장된 원소 수를 나타내는 `length` 또는 `size`로 구성된다.

### 핵심 해설

배열만 있으면 그냥 배열이고,
`length`까지 있어야 “리스트처럼 관리”할 수 있다.

### 실수 포인트

* 배열만 답하고 length를 빼먹는 것

### 실무 연결

버퍼도 결국 “저장 공간 + 현재 상태 정보”가 같이 있어야 한다.

---

## Q17. 순서리스트에서 삽입이 느린 이유

### 모범답안

순서리스트는 배열 기반이므로 중간 위치에 데이터를 삽입하려면 그 뒤의 원소들을 한 칸씩 뒤로 이동시켜야 한다.
그래서 최악의 경우 O(n)의 시간이 걸린다.

### 핵심 해설

삽입 자체보다 **밀기(shift)** 가 비용의 핵심이다.

### 실수 포인트

* 무조건 O(1)처럼 생각하는 것

### 실무 연결

배열 기반 구조에서 중간 삽입이 많으면 성능 저하가 생길 수 있다.

---

## Q18. 순서리스트에서 삭제가 느린 이유

### 모범답안

중간 원소를 삭제하면 그 뒤에 있는 원소들을 앞쪽으로 당겨 빈 공간을 메워야 하기 때문이다.
그래서 삭제 후에도 데이터의 순서를 유지하려면 O(n)의 이동이 필요하다.

### 핵심 해설

삭제도 결국 “앞으로 당기기”가 비용이다.

### 실수 포인트

* 삭제는 그냥 값 하나 지우는 것이라고 생각하는 것

### 실무 연결

논리적으로 빈칸이 생기지 않게 유지하려면 이동이 필요하다.

---

## Q19. 순서리스트의 장점

### 모범답안

순서리스트는 인덱스를 통한 직접 접근이 빠르고, 구조가 단순하여 구현과 관리가 쉽다.
또한 메모리가 연속적이어서 캐시 효율 측면에서도 유리할 수 있다.

### 핵심 해설

순서리스트의 강점은 **접근 속도와 단순성**이다.

### 실수 포인트

* 삽입/삭제 단점만 기억하고 장점을 빼먹는 것

### 실무 연결

고정 길이 테이블, 설정값 배열, 버퍼 관리에 잘 맞는다.

---

## Q20. 단순 연결리스트 노드 구조

### 모범답안

단순 연결리스트의 노드는 보통 데이터와 다음 노드를 가리키는 포인터 `next`를 가진다.

### 핵심 해설

노드 하나가 원소 하나다.

### 실수 포인트

* head를 노드 멤버로 넣어서 설명하는 것

### 실무 연결

`data + next` 구조는 연결리스트의 최소 단위다.

## Q21. head 포인터의 의미

### 모범답안

`head`는 연결리스트의 첫 번째 노드를 가리키는 포인터이며, 리스트 전체에 접근하기 위한 시작점이다.

### 핵심 해설

head를 잃으면 리스트 전체를 잃는다.

### 실수 포인트

* head를 데이터 저장소처럼 설명하는 것

### 실무 연결

head는 리스트 자체가 아니라 “리스트의 시작 주소”다.

---

## Q22. 공집합 연결리스트 생성

### 모범답안

빈 연결리스트는 아직 어떤 노드도 연결되어 있지 않으므로 `head = NULL` 로 초기화한다.

### 핵심 해설

NULL은 “아직 유효한 첫 노드가 없음”을 의미한다.

### 실수 포인트

* `head->next = NULL` 로 시작하려는 것
  head 자체가 없는데 역참조부터 하면 안 된다.

### 실무 연결

초기화 실수는 세그먼트 오류의 시작점이 된다.

---

## Q23. 노드 추가 시 `current == NULL` 인 경우

### 모범답안

`current == NULL` 은 보통 현재 가리키는 노드가 없다는 뜻으로, 빈 리스트이거나 순회가 끝나 더 이상 다음 노드가 없는 상황을 의미한다.
반면 `current != NULL` 이면 유효한 노드를 가리키고 있으므로 데이터를 읽거나 `next`를 따라갈 수 있다.

### 핵심 해설

NULL은 “끝”이거나 “없음”이다.

### 실수 포인트

* `current == NULL` 과 `current->next == NULL` 을 같은 뜻으로 보는 것

### 실무 연결

* `current == NULL` → 현재 노드 없음
* `current->next == NULL` → 현재 노드는 있고, 그 다음이 없음

## Q24. 마지막 노드 추가 로직 설명

### 모범답안

마지막 노드 추가는 먼저 새 노드를 동적 할당하고 데이터를 저장한 뒤 `next = NULL` 로 초기화한다.
빈 리스트라면 `head = new_node` 로 연결하고, 비어 있지 않다면 마지막 노드를 순회로 찾은 뒤 그 노드의 `next`를 새 노드로 연결한다.

### 핵심 해설

“빈 리스트 처리”와 “일반 경우 처리”를 나눠서 설명해야 한다.

### 실수 포인트

* 마지막 노드 찾는 과정을 생략하는 것

### 실무 연결

append 로직은 연결리스트 설명의 기본이다.

## Q25. 왜 새 노드마다 `malloc`이 필요한가?

### 모범답안

연결리스트의 각 노드는 실행 중 필요할 때마다 새로 생성되므로, 고정 배열이 아니라 동적 메모리 할당이 필요하다.
`malloc`을 통해 새로운 노드가 저장될 힙 메모리를 확보해야 노드를 리스트에 연결할 수 있다.

### 핵심 해설

연결리스트는 “미리 다 만들어두는 구조”가 아니다.

### 실수 포인트

* 포인터 변수 선언만 하면 노드가 생긴다고 착각하는 것

### 실무 연결

포인터는 주소를 담는 변수일 뿐이고, 실제 노드 공간은 따로 확보해야 한다.

## Q26. 같은 포인터 변수명을 계속 써도 되나?

### 모범답안

포인터 변수명은 단지 현재 새로 할당한 노드의 주소를 잠시 담는 변수일 뿐이므로, 반복문 안에서 같은 변수명을 재사용해도 문제 없다.
이전에 생성된 노드들은 이미 연결리스트 내부의 `next` 링크를 통해 유지되므로 사라지지 않는다.

### 핵심 해설

구분해야 할 것은:

* 포인터 변수 자체
* 포인터가 가리키는 힙 메모리

### 실수 포인트

* 변수명이 덮어써지면 이전 노드도 없어지는 줄 아는 것

### 실무 연결

`new_node` 이름을 반복 사용해도, 링크만 잘 연결되어 있으면 괜찮다.

## Q27. 이중 연결리스트 노드 구조

### 모범답안

이중 연결리스트 노드는 데이터와 다음 노드를 가리키는 `next`, 그리고 이전 노드를 가리키는 `prev` 포인터를 가진다.

### 핵심 해설

단순 연결리스트와의 차이는 `prev` 하나다.

### 실수 포인트

* head와 tail을 노드 멤버로 착각하는 것

### 실무 연결

양방향 탐색과 삭제 편의성을 위해 prev가 추가된다.

## Q28. 이중 연결리스트의 장점

### 모범답안

이중 연결리스트는 앞뒤 양방향으로 이동할 수 있고, 특정 노드를 알고 있을 때 이전 노드에 쉽게 접근할 수 있어 삽입/삭제가 더 편리하다.

### 핵심 해설

`prev`가 추가되면서 탐색 방향과 삭제 편의성이 좋아진다.

### 실수 포인트

* “무조건 더 빠르다”라고 말하는 것

### 실무 연결

undo/redo, 브라우저 이동 같은 구조에 잘 맞는다.

---

## Q29. 이중 연결리스트의 단점

### 모범답안

이중 연결리스트는 `prev` 포인터가 추가되므로 메모리 사용량이 증가하고, 삽입/삭제 시 갱신해야 할 링크 수가 많아 구현이 더 복잡하다.

### 핵심 해설

장점은 편의성, 단점은 복잡성과 메모리 증가다.

### 실수 포인트

* 단점 없이 상위 호환처럼 생각하는 것

### 실무 연결

포인터 실수 가능성이 늘어나므로 디버깅 부담도 커진다.

## Q30. 삭제 시 왜 이중 연결리스트가 편한가?

### 모범답안

삭제 대상 노드를 이미 알고 있다면, 이중 연결리스트는 그 노드의 `prev`와 `next`를 이용해 바로 앞뒤를 연결할 수 있다.
반면 단순 연결리스트는 삭제 대상의 이전 노드를 따로 찾아야 하는 경우가 많아 더 번거롭다.

### 핵심 해설

이 질문의 키워드는 **이전 노드 탐색 불필요**다.

### 실수 포인트

* 단순 연결리스트도 똑같다고 말하는 것

### 실무 연결

삭제가 많은 구조에서는 이 차이가 커질 수 있다.

# Part 6. 서술형 / 면접형 정답 해설

## Q40. 배열과 연결리스트 중 뭐가 더 좋은가?

### 모범답안

둘 중 하나가 무조건 더 좋은 것은 아니고, 사용 목적에 따라 다르다.
배열은 인덱스 접근이 빠르고 구조가 단순하지만 크기가 고정적이고 중간 삽입/삭제가 불리하다.
연결리스트는 크기를 유동적으로 늘릴 수 있고 삽입/삭제가 유리하지만, 임의 접근이 느리고 포인터 관리가 필요하다.

### 핵심 해설

반드시 “상황에 따라 다르다”로 시작하는 게 좋다.

---

## Q41. 왜 연결리스트는 인덱스 접근이 느린가?

### 모범답안

연결리스트는 메모리에 연속 저장되지 않고 각 노드가 포인터로 연결되어 있으므로, 특정 위치의 원소에 가려면 head부터 차례로 따라가야 한다.
그래서 배열처럼 주소 계산으로 바로 접근할 수 없다.

### 핵심 해설

배열은 직접 접근, 연결리스트는 순차 접근이다.

---

## Q42. 이중 연결리스트는 언제 쓰나?

### 모범답안

이중 연결리스트는 앞뒤 양방향 이동이 필요한 경우나, 특정 노드를 기준으로 앞뒤 삽입/삭제가 자주 일어나는 경우에 적합하다.
예를 들어 브라우저의 뒤로가기/앞으로가기, undo/redo 같은 구조에서 유용하다.

### 핵심 해설

실무 예시 하나만 붙여도 답이 훨씬 강해진다.

**정답: X**

# 시험 직전 1페이지 요약

```text
[Ch1~3 핵심 압축 정리]

1. 자료구조는 데이터를 효율적으로 저장하고 처리하기 위한 구조이다.
2. 자료구조는 저장 방식, 알고리즘은 처리 절차이다.
3. 시간복잡도는 입력 크기 증가에 따른 연산량 변화를 나타낸다.
4. 배열은 연속 메모리라 인덱스 접근이 빠르다.
5. 포인터는 주소 전달, 동적 메모리, 연결구조 구현에 필요하다.
6. 순서리스트는 배열 + length 로 표현한다.
7. 공집합 순서리스트는 length == 0 이다.
8. 단순 연결리스트는 data + next 로 구성된다.
9. 공집합 연결리스트는 head == NULL 이다.
10. 이중 연결리스트는 prev + next 를 가져 양방향 이동이 가능하다.
11. 배열은 접근이 빠르고, 연결리스트는 삽입/삭제와 크기 유동성에 유리하다.
12. 연결리스트에서 free 순서와 head 보존은 매우 중요하다.
```
