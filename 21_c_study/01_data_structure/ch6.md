좋아.
이번 요청 아주 좋다. **파일 변환 안 하고**,
그 대신 **노션에 바로 붙여넣기 가능한 “학습 교재형 정리본”** 으로 가는 게 맞다.

그리고 네 판단이 맞아.
지금부터는 **토큰을 파일 변환에 쓰는 것보다, 내용 밀도를 올리는 게 훨씬 이득**이다.

### **이번 파트 3단 분할**

2. **Heap = “우선순위 관리용 완전이진트리”**
3. **m-way 탐색트리 = “노드 하나에 여러 키를 넣어 높이를 줄이는 구조”**

즉,

* **BST는 검색/삽입/삭제 로직**
* **Heap은 부모-자식 우선순위 유지**
* **m-way는 높이 줄여서 디스크/대용량 탐색 효율**

이렇게 **목적 기준**으로 쪼개야 안 헷갈린다.

# Ch6-2. 트리와 이진트리 응용 (BST / Heap / m-way 탐색트리)

> **학습 목표**

* 이진탐색트리(BST)의 구조와 탐색/삽입/삭제를 이해한다.
* 히프(Heap)가 BST와 다른 목적의 트리라는 점을 구분한다.
* m원 탐색트리가 왜 필요한지 “트리 높이 감소” 관점에서 이해한다.
* 각 구조를 **“언제 쓰는지”** 기준으로 설명할 수 있다.

---

# 1. 이 파트 전체를 보는 핵심 관점

트리 응용 파트는 **“모양”보다 “목적”** 으로 구분해야 한다.

| 구조               |         핵심 목적 |          핵심 특징 |
| ---------------- | ------------: | -------------: |
| **이진탐색트리 (BST)** |         빠른 탐색 |  왼쪽 < 루트 < 오른쪽 |
| **히프 (Heap)**    |    우선순위 빠른 처리 | 부모-자식 대소 관계 유지 |
| **m원 탐색트리**      | 높이 감소, 대용량 탐색 | 노드 하나에 여러 키 저장 |

> **핵심 한 줄**
>
> * **BST = 검색 트리**
> * **Heap = 우선순위 트리**
> * **m-way = 높이 줄이는 탐색 트리**

---

# 2. 이진탐색트리 (Binary Search Tree, BST)

---

## 2-1. 정의

이진탐색트리는 **이진트리의 한 종류**로,
각 노드가 가진 **키(key)** 값을 기준으로 다음 규칙을 만족한다.

### BST 규칙

* **왼쪽 서브트리의 모든 키 < 현재 노드 키**
* **오른쪽 서브트리의 모든 키 > 현재 노드 키**
* 왼쪽/오른쪽 서브트리도 각각 BST이다.

---

## 2-2. 노드의 키값이란?

여기서 말하는 **키(key)** 는
노드를 비교하고 탐색하는 기준이 되는 값이다.

예:

* 학생 구조체에서 `학번`
* 상품 구조체에서 `상품코드`
* 사용자 구조체에서 `ID`

즉,

```text
노드 전체 데이터 = { 키 + 기타 정보 }
탐색 기준 = 키
```

### 예시

```c
typedef struct Node {
    int key;            // 탐색 기준
    char name[20];      // 부가 정보
    struct Node *left;
    struct Node *right;
} Node;
```

> **핵심**
>
> * BST는 “노드 전체”를 비교하는 게 아니라
> * **보통 key를 기준으로 비교한다**

---

## 2-3. BST 탐색

BST 탐색은 배열의 이진탐색처럼
**한 번 비교할 때마다 왼쪽/오른쪽 한쪽만 선택**한다.

### 탐색 규칙

* 찾는 key == 현재 노드 key → 성공
* 찾는 key < 현재 노드 key → 왼쪽 이동
* 찾는 key > 현재 노드 key → 오른쪽 이동

### 직관

```text
50
├─ left: 30
└─ right: 70
```

`30` 찾기:

* 50보다 작음 → 왼쪽
* 30 도착 → 성공

---

## 2-4. BST 노드 추가 (삽입)

삽입은 **탐색과 거의 동일**하다.

### 절차

1. 루트부터 시작
2. key 비교
3. 왼쪽/오른쪽으로 내려감
4. **NULL 위치**를 만나면 거기에 새 노드 삽입

### 핵심

* “삽입 위치를 찾는 과정” = 탐색
* 마지막에 `NULL` 자리에 연결

> **암기 포인트**
> BST 삽입은
> **“탐색하다가 비어 있는 자리(NULL)를 만나면 삽입”**

---

## 2-5. BST 삭제 — 가장 중요한 파트

삭제는 무조건 **3가지 경우**로 나눠서 외워야 한다.

---

### (1) 삭제 대상이 리프 노드(leaf)

자식이 없는 노드.

### 처리

* 그냥 부모와의 연결 끊고 free

### 가장 쉬운 경우

---

### (2) 삭제 대상이 자식 1개만 가짐

예:

* 왼쪽 자식만 있음
* 또는 오른쪽 자식만 있음

### 처리

* 부모가 삭제 노드를 건너뛰고
* **삭제 노드의 유일한 자식**과 직접 연결

즉:

```text
부모 -> 삭제노드 -> 자식
```

를

```text
부모 -> 자식
```

으로 바꿈

---

### (3) 삭제 대상이 자식 2개 모두 가짐 ← 핵심

가장 헷갈리는 부분.

이 경우는 삭제 노드를 바로 없애면
BST 규칙 유지가 어렵다.

그래서 보통 아래 둘 중 하나를 사용:

* **중위순회 기준 전임자(inorder predecessor)**
  = 왼쪽 서브트리의 최댓값
* **중위순회 기준 후임자(inorder successor)**
  = 오른쪽 서브트리의 최솟값

### 많이 쓰는 방식

* **오른쪽 서브트리의 최솟값(successor)** 를 가져와서
* 삭제할 노드 자리에 복사
* 그 다음, 그 successor 노드를 삭제

> **핵심 한 줄**
> 자식 2개면
> **“바로 지우지 말고, 대체 노드(전임자/후임자)로 교체 후 삭제”**

---

# 3. BST 삭제 공부법 (실전 추천)

이건 네가 반드시 이렇게 봐야 한다.

### 1단계

“삭제는 3가지 경우”를 먼저 외움

* 리프
* 자식 1개
* 자식 2개

### 2단계

각 경우를 **그림으로 1번씩 직접 그리기**

### 3단계

코드 보기 전에 말로 설명

> “자식 2개면 successor 찾아서 값 복사 후 successor 삭제”

이 문장이 입에서 바로 나와야 함.

> **중요**
> BST 삭제는 처음부터 코드 외우면 망한다.
> **반드시 그림 → 말 → 코드** 순서로 가야 한다.

---

# 4. 이진탐색트리의 탐색 성능

---

## 4-1. 탐색 시간은 무엇에 비례하나?

BST의 탐색 성능은
**트리의 높이(height)** 에 비례한다.

즉,

* 루트에서 시작해서
* 아래로 한 단계씩 내려가므로
* 탐색 비용 ≈ **루트 → 리프까지 경로 길이**

---

## 4-2. 평균적으로는?

노드들이 **균형 있게 퍼져 있으면**

* 높이 ≈ `log₂ n`
* 탐색/삽입/삭제 ≈ **O(log n)**

그래서 BST가 빠르다.

---

## 4-3. 성능이 떨어지는 경우

키가 정렬된 순서대로 들어가면:

예:

* 10, 20, 30, 40, 50

트리가 이렇게 한쪽으로 치우칠 수 있다.

```text
10
 \
  20
   \
    30
     \
      40
       \
        50
```

이건 사실상 **연결리스트**처럼 됨.

### 이 경우

* 높이 ≈ n
* 탐색 성능 ≈ **O(n)**

> **핵심**
> BST는 **균형이 깨지면 성능이 급격히 나빠진다**

---

## 4-4. “탐색 성능이 떨어지지 않도록 지나치게 커지지 않게 해야 함”의 의미

네 메모 아주 중요.

이 말은 정확히는:

* **트리 높이가 너무 커지면 안 된다**
* 한쪽으로 치우친(skewed) 트리가 되면 안 된다

즉,

* 노드 수가 많아지는 것 자체가 문제라기보다
* **높이가 비정상적으로 커지는 것**이 문제

### 연결되는 개념

이걸 해결하려고 나중에 배우는 게:

* AVL Tree
* Red-Black Tree
* B-Tree 계열

즉, **균형 트리**가 나오는 이유가 바로 여기다.

---

# 5. 히프 (Heap)

---

## 5-1. 히프는 BST가 아니다

이거 무조건 구분해야 한다.

많이 헷갈리는 실수:

* “힙도 트리니까 검색 잘 되는 거 아닌가?”

❌ 아니다.

### 힙의 목적

* **최댓값 / 최솟값을 빠르게 꺼내기 위한 구조**
* 즉, **우선순위 처리**

> **핵심**
>
> * BST = 검색 최적화
> * Heap = 최댓값/최솟값 추출 최적화

---

## 5-2. 히프의 기본 구조

힙은 **완전 이진트리** 형태를 유지한다.

### 완전 이진트리란?

* 마지막 레벨만 덜 찰 수 있음
* 마지막 레벨도 **왼쪽부터 채움**

---

## 5-3. 힙의 종류

### 최대 히프 (Max Heap)

* 부모 ≥ 자식

### 최소 히프 (Min Heap)

* 부모 ≤ 자식

> **주의**
> 히프는 “부모-자식 관계”만 보장한다.
> 형제끼리, 서브트리 전체가 정렬된 건 아니다.

---

## 5-4. 왜 링크표현보다 순차표현(배열)을 많이 쓰나?

네 메모 핵심.

힙은 완전 이진트리라서 **배열 표현이 매우 잘 맞는다.**

### 배열 인덱스 관계 (1번 인덱스 기준)

* 부모: `i`
* 왼쪽 자식: `2i`
* 오른쪽 자식: `2i + 1`

이렇게 계산 가능하다.

그래서 굳이 `left`, `right` 포인터 없이도
배열만으로 트리 구조를 표현 가능하다.

> **핵심**
> 힙은 완전 이진트리라서
> **순차표현(배열)** 이 가장 자연스럽다.

---

## 5-5. 힙 추가 (삽입)

삽입은 보통 다음 순서:

1. 완전 이진트리 조건을 유지하기 위해
   **배열 맨 뒤(마지막 위치)** 에 삽입
2. 부모와 비교
3. 힙 조건이 깨지면 위로 올림

이걸 보통:

* **heapify-up**
* **up-heap**
* **bubble-up**

이라고 한다.

### 최대 힙 기준

* 새 노드가 부모보다 크면 swap
* 반복

---

## 5-6. 힙 삭제

보통 힙에서 삭제는
**루트 삭제**를 의미한다.
(최대 힙이면 최대값, 최소 힙이면 최소값)

### 절차

1. 루트 제거
2. 마지막 노드를 루트로 올림
3. 자식과 비교
4. 힙 조건이 깨지면 아래로 내림

이걸:

* **heapify-down**
* **down-heap**
* **bubble-down**

이라고 한다.

---

## 5-7. 힙 정렬과 연결

네 메모처럼
힙 정렬은 보통 뒤 챕터에서 더 자세히 보지만,
지금은 연결만 기억하면 된다.

### 핵심

* 힙 만들기
* 루트(최대/최소) 반복 제거
* 정렬 가능

> **지금 단계 목표**
> 힙 정렬을 깊게 외우지 말고
> **“힙은 우선순위 + 정렬과 연결된다”** 정도만 기억

---

# 6. BST vs Heap 구분 (중요)

이건 PDF/노션에서 박스로 외워야 한다.

| 항목       |           BST |           Heap |
| -------- | ------------: | -------------: |
| 목적       |         빠른 탐색 |    최대/최소 우선 추출 |
| 핵심 조건    | 왼쪽 < 루트 < 오른쪽 |     부모-자식 대소관계 |
| 전체 정렬 느낌 |    중위순회 시 정렬됨 |       전체 정렬 아님 |
| 대표 구현    |    링크표현 많이 사용 | 배열(순차표현) 많이 사용 |
| 균형 깨지면   |       성능 저하 큼 |      완전이진트리 유지 |

> **한 줄 요약**
>
> * **BST는 “찾기”**
> * **Heap은 “우선순위”**

---

# 7. m원 탐색트리 (m-way Search Tree)

---

## 7-1. 왜 나오나?

BST는 높이가 커지면 느려진다.

그래서 생각한 것:

> “노드 하나에 키를 여러 개 넣으면,
> 한 번 내려갈 때 더 많은 범위를 걸러낼 수 있지 않을까?”

이게 m원 탐색트리의 핵심 아이디어다.

---

## 7-2. 정의

m원 탐색트리는
**한 노드가 여러 개의 키를 가질 수 있고**,
그 키들 사이 구간에 따라 **최대 m개의 자식**을 가질 수 있는 탐색트리이다.

---

## 7-3. 4원 탐색트리 예시

4-way search tree 라면:

* 한 노드에 **최대 3개의 키**
* 자식은 **최대 4개**

예:

```text
[10 | 20 | 30]
 /    |    |   \
<10  10~20 20~30 >30
```

즉,

* 키가 10보다 작으면 첫 번째 자식
* 10~20 사이면 두 번째 자식
* 20~30 사이면 세 번째 자식
* 30보다 크면 네 번째 자식

> **핵심 공식**
>
> * 최대 자식 수 = **m**
> * 최대 키 수 = **m - 1**

---

## 7-4. m원 탐색트리 탐색

네 메모 그대로 정리하면:

### 절차

1. 현재 노드 방문
2. 노드 안의 키들을 **왼쪽부터 순차탐색**
3. 찾는 key와 같으면 성공
4. 처음으로 더 큰 키를 만나면, 그 왼쪽 구간의 자식으로 내려감
5. 끝까지 다 봤는데 더 크거나 같은 키가 없으면, 마지막 자식으로 내려감

### 즉

* 노드 내부에서는 **순차탐색**
* 노드 간 이동은 **트리 탐색**

---

## 7-5. m원 탐색트리 삽입 / 삭제

이 파트는 교재에서 자세히 나오면 복잡해질 수 있다.
지금 단계에서는 **개념만** 잡으면 충분하다.

### 삽입

* 적절한 리프 위치까지 탐색
* 노드에 여유가 있으면 키 삽입
* 꽉 차면 분할(split) 같은 개념이 연결될 수 있음
  (B-tree 계열로 이어짐)

### 삭제

* 키 제거
* 노드 최소 조건 깨지면 재배치/병합 가능
  (역시 B-tree 계열과 연결)

> **지금은 깊게 안 파도 된다**
> m원 탐색트리는
> **“B-tree 류로 가기 위한 사전 개념”** 으로 보는 게 맞다.

---

## 7-6. 탐색 성능

m원 탐색트리는 한 노드에 여러 키를 담기 때문에
**트리 높이를 더 낮출 수 있다.**

즉,

* BST보다
* 한 단계에서 더 많은 범위를 분기 가능
* 그래서 **깊이가 줄어드는 장점**

특히 디스크/파일 시스템/DB처럼
**한 번 내려가는 비용이 큰 환경**에서 유리하다.

> **핵심**
> m-way의 목적은
> **“한 노드에서 더 많이 비교해서, 트리 높이를 줄이는 것”**

# 9. 시험/면접형으로 말하는 답변 틀

---

## “BST와 힙 차이 설명해보세요”

**모범 틀**

> 이진탐색트리는 키 기준으로 왼쪽 서브트리는 작고 오른쪽 서브트리는 큰 구조를 유지해 탐색에 유리한 트리입니다.
> 반면 힙은 부모와 자식 간 대소관계만 유지하여 최대값 또는 최소값을 빠르게 꺼내기 위한 구조로, 전체 탐색용 정렬 구조는 아닙니다.

---

## “BST 삭제가 왜 어려운가요?”

**모범 틀**

> 삭제 후에도 BST의 정렬 규칙을 유지해야 하기 때문입니다.
> 특히 자식이 두 개인 경우에는 바로 삭제하지 않고, 중위순회 기준 전임자나 후임자로 대체한 뒤 해당 노드를 삭제해야 합니다.

---

## “왜 힙은 배열로 많이 구현하나요?”

**모범 틀**

> 힙은 완전 이진트리 구조이기 때문에 배열 인덱스로 부모-자식 관계를 계산할 수 있어 포인터 없이도 효율적으로 표현할 수 있기 때문입니다.

# 10. 암기용 초압축 요약 (노션 맨 아래 넣기 좋음)

```text
[Ch6-2 트리 응용 핵심 요약]

1. BST는 이진탐색트리로, 왼쪽 < 루트 < 오른쪽 규칙을 가진다.
2. BST의 key는 노드를 비교하고 탐색하는 기준 값이다.
3. BST 탐색/삽입은 비교 후 왼쪽 또는 오른쪽으로 내려간다.
4. BST 삽입은 탐색하다가 NULL 위치에 새 노드를 넣는다.
5. BST 삭제는 3가지 경우로 나눈다: 리프 / 자식 1개 / 자식 2개.
6. 자식 2개 삭제는 전임자(predecessor) 또는 후임자(successor)로 대체 후 삭제한다.
7. BST 성능은 트리 높이에 비례하며, 균형이 좋으면 O(log n), 치우치면 O(n)이다.
8. Heap은 BST와 다르며, 최대값/최소값을 빠르게 꺼내기 위한 구조이다.
9. Heap은 완전 이진트리이며, 보통 배열(순차표현)로 구현한다.
10. Heap 삽입은 up-heap, 삭제(루트)는 down-heap 과정이 핵심이다.
11. m-way 탐색트리는 한 노드에 여러 키를 저장해 트리 높이를 줄이는 구조이다.
12. m원 탐색트리는 최대 m개의 자식, 최대 m-1개의 키를 가진다.
13. m-way는 B-tree 계열을 이해하기 위한 사전 개념으로 보면 된다.
```
