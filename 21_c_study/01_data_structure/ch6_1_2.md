# 자료구조 Chapter 6-2

# 트리와 이진트리 응용 (BST / Heap / m-원 탐색트리)

### 학습용 정리 + 코드 학습 가이드 (노션 복붙용)

---

# 1. 이번 범위의 큰 그림

이번 범위는 **“트리의 응용”** 이다.
즉, 트리를 단순히 **부모-자식 구조**로만 보는 게 아니라,
**탐색 / 우선순위 / 대용량 탐색** 문제를 해결하는 도구로 보는 파트다.

이번 챕터의 핵심 구조는 다음 3가지다.

* **이진탐색트리(BST)**
  → 정렬 상태를 유지하면서 빠르게 탐색하기 위한 트리

* **힙(Heap)**
  → 최대값 / 최소값을 빠르게 꺼내기 위한 완전 이진트리 기반 구조

* **m-원 탐색트리(m-way search tree)**
  → 한 노드 안에 여러 키를 저장하여 탐색 효율을 높이는 구조

---

# 2. 이 챕터를 어떻게 공부해야 하는가

이 챕터는 **“트리 종류 외우기”** 로 공부하면 망한다.
반드시 아래 관점으로 봐야 한다.

## 2-1. 핵심 질문 3개

### 1) 왜 이 구조가 필요한가?

* BST → **탐색**
* Heap → **우선순위 처리**
* m-원 탐색트리 → **더 큰 규모의 탐색**

### 2) 어떤 규칙이 있는가?

* BST → 왼쪽 < 루트 < 오른쪽
* Heap → 부모 ≥ 자식(최대힙 기준)
* m-way → 노드 내부 키들이 정렬되어 있고, 그 사이 구간마다 자식이 나뉨

### 3) 어떤 연산이 중요한가?

* BST → 탐색 / 삽입 / 삭제
* Heap → 삽입 / 루트 삭제
* m-way → 탐색 / (개념적으로) 삽입 / 삭제

---

# 3. 1순위로 잡아야 할 구조: 이진탐색트리(BST)

---

## 3-1. BST의 정의

이진탐색트리(Binary Search Tree)는
**각 노드의 왼쪽 서브트리에는 더 작은 값**,
**오른쪽 서브트리에는 더 큰 값** 이 저장되는 이진트리다.

즉:

* 왼쪽 서브트리의 모든 키 < 현재 노드 키
* 오른쪽 서브트리의 모든 키 > 현재 노드 키

이 규칙 덕분에 탐색을 할 때
**비교하면서 한쪽 서브트리만 내려가면 된다.**

---

## 3-2. BST에서 말하는 “노드의 키값(key)”

BST에서 **키(key)** 는
**탐색 / 삽입 / 삭제의 기준이 되는 값** 이다.

예를 들어 구조체가 다음과 같다면:

```c
typedef struct BSTNode {
    int key;
    struct BSTNode *left;
    struct BSTNode *right;
} BSTNode;
```

여기서 `key` 가 바로 **정렬과 비교의 기준값** 이다.

### 쉽게 기억

* 데이터(data): 저장된 내용 전체
* 키(key): 비교 기준이 되는 값

실무에서는 구조체 안에 이렇게 확장될 수도 있다:

```c
typedef struct StudentNode {
    int student_id;   // key 역할
    char name[50];
    int score;
    struct StudentNode *left;
    struct StudentNode *right;
} StudentNode;
```

이 경우 `student_id` 가 키값 역할을 한다.

---

## 3-3. BST 탐색

BST 탐색은 **루트부터 시작해서 비교하며 내려가는 방식** 이다.

### 탐색 규칙

* 찾는 값 == 현재 노드 → 성공
* 찾는 값 < 현재 노드 → 왼쪽 이동
* 찾는 값 > 현재 노드 → 오른쪽 이동

### 핵심 포인트

BST는 **매번 한쪽만 선택** 하므로
일반 이진트리보다 탐색이 빠르다.

---

## 3-4. BST 삽입

삽입도 탐색과 똑같이 시작한다.

### 삽입 과정

1. 루트부터 시작
2. 비교하면서 왼쪽 또는 오른쪽으로 이동
3. NULL 위치를 만나면 그 자리에 새 노드 삽입

### 핵심

* **BST 규칙을 유지해야 한다**
* 중복 키는 보통

  * 삽입 안 함
  * 또는 카운트 증가
  * 또는 한쪽으로 몰아서 처리
    중 하나를 정한다

초급 단계에서는 **“중복 키 삽입 안 함”** 으로 보는 게 제일 깔끔하다.

---

## 3-5. BST 삭제 (가장 중요)

삭제는 이 챕터에서 가장 중요하다.
반드시 **3가지 경우** 를 구분해야 한다.

---

### Case 1. 삭제 노드가 리프 노드인 경우

즉, 자식이 없는 경우.

### 처리

* 그냥 삭제하면 끝

### 이유

* 연결을 바꿀 하위 구조가 없음

---

### Case 2. 삭제 노드가 자식 1개만 갖는 경우

즉,

* 왼쪽 자식만 있거나
* 오른쪽 자식만 있는 경우

### 처리

* 삭제할 노드를 제거하고
* 그 자식을 부모와 직접 연결

### 핵심

* **삭제 노드를 자식이 대신한다**

---

### Case 3. 삭제 노드가 자식 2개를 모두 갖는 경우

가장 까다롭다.

### 대표 처리 방법

* **오른쪽 서브트리의 최소값(중위 후계자, inorder successor)** 을 가져와서
* 삭제할 노드의 값을 대체
* 그 후계자 노드를 실제로 삭제

또는 반대로

* **왼쪽 서브트리의 최대값(중위 전임자)** 를 써도 된다

### 왜 이렇게 하나?

삭제 노드 자리에 아무 값이나 넣으면
BST 정렬 규칙이 깨지기 때문.

---

## 3-6. BST의 성능

BST는 보통 **트리 높이(height)** 에 비례한다.

### 평균적으로

* 탐색 / 삽입 / 삭제: **O(log n)** 에 가깝게 기대

### 최악의 경우

트리가 한쪽으로 치우치면:

* 탐색 / 삽입 / 삭제: **O(n)**

즉,
**BST는 “항상 빠른 트리”가 아니라, “균형이 어느 정도 유지될 때 빠른 트리”** 다.

---

## 3-7. 왜 “루트 → 리프 경로 길이”가 중요한가?

탐색은 결국
**루트에서 시작해서 리프 방향으로 내려가는 과정** 이다.

따라서 성능은 사실상

* 얼마나 깊이 내려가야 하는가
* 즉, **트리 높이**

에 의해 결정된다.

### 기억 포인트

* 트리가 낮고 균형 잡힘 → 빠름
* 트리가 길고 치우침 → 느림

---

# 4. 2순위로 잡아야 할 구조: 힙(Heap)

---

## 4-1. 힙이란?

힙(Heap)은 **완전 이진트리** 를 기반으로 하는 자료구조다.

대표적으로:

* **최대힙(Max Heap)**: 부모 ≥ 자식
* **최소힙(Min Heap)**: 부모 ≤ 자식

### 중요한 점

힙은 **BST처럼 좌우 정렬 구조가 아니다.**

즉:

* 왼쪽이 무조건 작다 / 오른쪽이 무조건 크다 → ❌
* 부모와 자식 사이의 우선순위만 보장 → ✅

---

## 4-2. 왜 힙은 완전 이진트리여야 하는가?

힙은 보통 **배열(순차표현)** 로 구현한다.

완전 이진트리이면
배열 인덱스로 부모/자식을 계산하기 쉬워진다.

### 1번 인덱스 기준

* 부모 = `i / 2`
* 왼쪽 자식 = `2 * i`
* 오른쪽 자식 = `2 * i + 1`

### 0번 인덱스 기준

* 부모 = `(i - 1) / 2`
* 왼쪽 자식 = `2 * i + 1`
* 오른쪽 자식 = `2 * i + 2`

### 핵심

힙은 **링크 표현보다 순차표현(배열)** 이 훨씬 자연스럽다.

---

## 4-3. 힙 삽입

힙 삽입은 단순히 BST처럼 비교하며 내려가는 방식이 아니다.

### 최대힙 삽입 과정

1. **완전 이진트리 구조 유지** 를 위해 맨 마지막 위치에 삽입
2. 부모와 비교
3. 부모보다 크면 자리 교환
4. 이 과정을 반복하며 위로 올라감

이 과정을 보통:

* **heapify-up**
* **bubble-up**
* **percolate-up**

이라고 부른다.

---

## 4-4. 힙 삭제 (루트 삭제)

힙에서 가장 중요한 삭제는 **루트 삭제** 다.

최대힙이면 루트가 최대값이므로
“가장 큰 값 꺼내기” 가 핵심 연산이 된다.

### 최대힙 루트 삭제 과정

1. 루트 값을 꺼냄
2. 마지막 원소를 루트로 올림
3. 자식들과 비교
4. 더 큰 자식과 교환
5. 아래로 내려가며 힙 조건 복구

이 과정을 보통:

* **heapify-down**
* **bubble-down**
* **percolate-down**

이라고 한다.

---

## 4-5. 힙의 성능

* 삽입: **O(log n)**
* 루트 삭제: **O(log n)**
* 루트 확인(peek): **O(1)**

### 핵심 해석

힙은

* **전체 탐색용 구조가 아니라**
* **최대/최소 우선순위 처리 구조** 다

즉:

* BST → 특정 값 찾기 강함
* Heap → 제일 큰 값 / 제일 작은 값 꺼내기 강함

---

## 4-6. 힙 정렬은 어디와 연결되는가?

힙은 나중에 **힙 정렬(heap sort)** 로 연결된다.

흐름은 보통:

1. 힙 구성
2. 루트(최댓값 또는 최솟값) 반복 삭제
3. 정렬 결과 생성

네가 적어둔 **“힙 정렬 → 10장 참고”** 는
지금은 **힙의 삽입/삭제 원리만 이해** 하면 충분하다.

---

# 5. 3순위로 잡아야 할 구조: m-원 탐색트리

---

## 5-1. m-원 탐색트리란?

m-원 탐색트리는
**한 노드가 여러 개의 키와 여러 개의 자식 포인터를 가질 수 있는 탐색트리** 다.

### 예: 4원 탐색트리

* 한 노드에 최대 **3개의 키**
* 최대 **4개의 자식**

즉:

* 키 3개 → 자식 구간 4개

---

## 5-2. 4원 탐색트리를 어떻게 해석해야 하는가?

예를 들어 한 노드에 다음 키가 있다고 하자.

`[20, 50, 80]`

그러면 자식은 4개 구간으로 나뉜다.

* child0: 20보다 작은 값들
* child1: 20과 50 사이 값들
* child2: 50과 80 사이 값들
* child3: 80보다 큰 값들

### 핵심

**키 사이 구간마다 자식이 하나씩 생긴다.**

---

## 5-3. m-원 탐색트리 탐색

교재에서 말한 이 부분이 핵심이다.

> 루트 방문 →
> key와 같거나 처음으로 큰 키를 찾을 때까지
> 노드 내부의 키들을 순차탐색 →
> 해당 자식으로 이동

### 쉽게 말하면

1. 노드에 들어간다
2. 그 노드 안의 키들을 왼쪽부터 본다
3. 같으면 성공
4. 처음으로 더 큰 키를 만나면 그 왼쪽 자식으로 내려간다
5. 끝까지 다 작으면 맨 마지막 자식으로 내려간다

즉,
**“노드 내부 탐색 + 자식 분기”** 가 핵심이다.

---

## 5-4. m-원 탐색트리 삽입/삭제는 지금 어디까지 이해하면 되는가?

현재 단계에서는 **완전 구현보다 개념 이해가 우선** 이다.

### 지금 꼭 이해할 것

* 노드가 꽉 차면 어떻게 될까?
  → 실제 구현에서는 **분할(split)** 같은 처리가 필요
* 삭제하면 키 재배치 / 병합이 왜 필요할까?
  → 구조 규칙을 유지해야 하기 때문

### 지금 단계의 목표

* “한 노드에 여러 키를 둔다”
* “노드 내부 비교 후 자식으로 내려간다”
* “BST를 확장한 구조다”

이 정도면 충분하다.

---

# 6. 세 구조를 한 번에 비교하기

| 구조       |      핵심 목적 | 구조 규칙              | 대표 연산        | 구현 포인트     |
| -------- | ---------: | ------------------ | ------------ | ---------- |
| BST      |    특정 값 탐색 | 왼쪽 < 루트 < 오른쪽      | 탐색 / 삽입 / 삭제 | 링크 표현, 재귀  |
| Heap     | 최대/최소 우선순위 | 부모 ≥ 자식 (또는 ≤)     | 삽입 / 루트 삭제   | 배열 표현      |
| m-원 탐색트리 |  대용량 탐색 확장 | 노드 안에 여러 키 + 여러 자식 | 탐색 / 삽입 / 삭제 | 노드 내부 순차탐색 |

# 7. 이 챕터를 코드로 공부할 때 보는 순서

이 챕터는 **코드 전체를 한 번에 읽지 말고**,
반드시 아래 순서로 봐야 한다.

---

## 7-1. 1단계: BST만 먼저 본다

### 먼저 볼 함수

* `bst_search()`
* `bst_insert()`
* `bst_delete()`

### 체크 포인트

* 왜 `root = bst_insert(root, key)` 인가?
* 왜 삭제 함수가 `BSTNode*` 를 반환하는가?
* 왜 두 자식 삭제에서 후계자를 쓰는가?

### 암기 포인트

**BST 삭제 3케이스**

1. 리프 → 바로 삭제
2. 자식 1개 → 자식이 대체
3. 자식 2개 → 후계자/전임자로 대체 후 재삭제

---

## 7-2. 2단계: Heap 본다

### 먼저 볼 함수

* `heap_insert()`
* `heap_delete_root()`

### 외워야 할 것

(0번 인덱스 기준)

* 부모: `(i - 1) / 2`
* 왼쪽 자식: `2*i + 1`
* 오른쪽 자식: `2*i + 2`

### 핵심 감각

힙은 “정렬 트리”가 아니라
**우선순위 트리** 다.

---

## 7-3. 3단계: m-원 탐색트리는 탐색만 본다

### 먼저 볼 함수

* `mway_search()`

### 지금 중요한 것

* 노드 안에서 먼저 비교

# 8. 시험 직전 1페이지 요약

* **BST** 는 왼쪽 < 루트 < 오른쪽 규칙을 가진 탐색 트리이다.
* BST의 중위순회 결과는 **오름차순** 이다.
* BST 삭제는 반드시 **리프 / 자식 1개 / 자식 2개** 3케이스로 구분한다.
* BST는 평균적으로 빠르지만, 한쪽으로 치우치면 성능이 나빠진다.
* **힙** 은 완전 이진트리 기반이며, 보통 **배열** 로 구현한다.
* 최대힙은 **부모 ≥ 자식**, 최소힙은 **부모 ≤ 자식** 이다.
* 힙 삽입은 **맨 뒤 삽입 후 위로 올림(heapify-up)** 이다.
* 힙 삭제는 **루트 삭제 후 마지막 원소를 루트로 올리고 아래로 내림(heapify-down)** 이다.
* **m-원 탐색트리** 는 한 노드에 여러 키를 저장하고, 키 사이 구간별로 자식을 둔다.
* 4원 탐색트리는 보통 **최대 3개 키 + 최대 4개 자식** 으로 이해한다.
* m-원 탐색트리는 **노드 내부 순차탐색 → 자식 분기** 가 핵심이다.
